# §0.3 你按下回车之后，模型做了什么？——打分、抽样与一次回答的来历 ▽

同一个问题问两遍，答案常常不一样；换个会话，它又“忘了”之前说过什么；偶尔它还会把没有的事说得像真的。这三个日常困惑有一个共同的源头：一次回答是怎么被造出来的。这一章把从按下回车到第一个字出现之间的几步拆开。拆完，三个困惑都能顺着同一条因果链自己答出来。

## 输入先变成 token，上下文是模型唯一能看到的

按下回车，你那段话先被切成 token（§0.1 立过：最小的文字小块），连同这一场对话里已有的内容（会话开头立的规矩与角色：聊天产品里由提供方预设，用接口时由你自己写；你早先的问题、它早先的回答）排成一串，作为模型的输入。这串输入就是上下文（§0.1 立过：模型此刻读到的全部文字）。它有容量上限，行话叫**上下文窗口**：超出窗口的部分进不来，模型看不见。

模型没有另一条记忆通道。凡是它此刻知道的，都在这串文字里；不在这串文字里的，它此刻不知道。换个会话它就“忘了”，原因就在这里：新会话的上下文里没有旧会话的内容。产品里那种“记得你”的体验，是系统在每次请求前把历史对话或它的摘要重新装进上下文。装进来它才看得见，不装就等于没发生过。

## 模型做的事：给下一个字打分

输入就位，模型做它唯一会做的事：接着这串文字往下续（§0.1 立过接龙的规矩）。它不是从某个答案库里挑一篇现成的，而是对着词表里的每个候选 token 各估一个分数：“接下来是它”的可能性有多高。词表是模型认识的全部 token 的名单，有几万条，就有几万个分数；token 多数是一个字，也有的是半个词或一个符号（§0.1 立过的“最小的文字小块”），下文说“字”，指的都是它。分数由参数算出（§0.1 立过），同一段输入、同一组参数，分数每次都一样。模型本身没有骰子。

## 分数变概率：Softmax 一步

几万个分数不便比较，先换算成概率：分数高的概率高，全体加起来等于一。这一步叫 Softmax：换算之后，最可能的字拿走最大的一份份额，但通常不通吃，第二名、第三名也各有一点。

## 落笔那一步：按概率抽一个字

真正让两次回答不一样的，是最后这一步。模型并不总取分数最高的字，而是**按概率抽一个**：份额大的字被抽中的机会大，份额小的也有机会。抽中的字接回输入末尾，模型对着长了一格的上下文重新打分、再抽。一段长回答，就是几百轮“打分—抽样—接回”。停下来也是同一条链：词表里有一个专门的结束记号，它照样被打分、被抽样，抽中它，回答就收尾；写满长度上限是另一道闸。

顺着这条链能推出三件事。其一，同一个问题两次回答不同，不是模型改了主意，是同一份概率摇出了不同的字。其二，开头的小分叉会一路放大：后面每一轮都看着已经生成的文字打分，第一步选了不同的字，后面就顺着不同的路走，长回答的后半段因此可能差得很远。其三，把抽样关掉、永远取分数最高的字，回答是稳了，却容易原地打转：回答里一旦冒出重复的短语，后面每轮都看着几乎同样的前文打分，名次几乎不变，同一串短语就翻来覆去。稳和活，是同一步的两种代价。

## 温度：把分数的差距拉大或抹平

抽样前还有一个可调的刻度，叫**温度**。它做的事很具体：分数先除以温度，再变概率。温度低，分数的差距被拉大，第一名几乎通吃，回答稳定；温度高，差距被抹平，排在后面的字也分到像样的份额，回答发散。

所以温度不是“创造力开关”，它只改选字的口子。事实类的问题把温度调高不会变准，只会让错处更花。答案对不对，取决于模型知不知道这件事；温度只管知道之后怎么说。写东西、想点子时调高温度，换来多样的候选，代价是更难预测。

温度压到零（或极低），份额几乎全挤给第一名，等于永远取最大。多数服务在低温下输出稳定，但低温换的是稳定，不是逐字复现的承诺。提供模型的那一侧会把多个请求合并处理，小数在机器里相加也有先后次序——这属实现层的误差，不是打分的设计里有随机。

## 候选名单先截短：top-k 与 top-p

光调温度还不够。名单排在后面的那串小概率候选，行话叫长尾；长尾里总有些怪字带着小概率被摇中。一句话开头正经，中间忽然蹦出个不相干的词，多半就是它们摇中的。两条截法先把名单砍短：**top-k** 只留分数最高的 k 个候选，其余出局；**top-p** 不定个数、定比例：按概率从大到小排队，加够一个比例就截断。概率集中时名单自动变短，分散时自动放长。工程上的常见默认是中等温度配 top-p：留多样性，砍怪字。它与温度都作用在抽样这一步，合起来就是那道口子：温度定份额的差距多悬殊，截断定名单里还剩谁。

## 它为什么会一本正经地编

打分—抽样这条链还能解释一个更让人不安的现象：模型会把没有的事说得像真的。它没有“这里我不知道”的天然开关；训练教它的是接一段像样的下文，而在它不知道答案时，一段像样的下文恰恰就是编一个说得通的。行话把这叫**幻觉**。它不是模型的怪癖，是训练目标与评估口径一起养出来的。

日常防它，办法不在调温度，在两件。把要用的资料放进上下文，它看得见就不用猜；对要紧的说法留一个核对动作，看出处是不是可靠，看数字经不经得起复算。

## 一次回答的全程，折成一张表

| 步骤 | 发生什么 | 使用者能调什么 |
| --- | --- | --- |
| 输入 | 切 token、装上下文，窗口外的进不来 | 给它什么材料、给多少；把任务说明白（§0.4、§7） |
| 打分 | 每个候选字一个分数，参数决定，没有随机 | 换模型；同一段话换个说法，分数也会变（§7） |
| 变概率 | Softmax 把分数换成份额 | 无（公式 §3） |
| 抽样 | 按份额抽一个字，接回，再打分 | 温度、top-k、top-p |
| 停 | 结束记号被抽中，或写满长度上限 | 回答长度（§9 讲服务端的账） |

五个步骤里，设计内的随机只有抽样一步；实现层的浮点与批处理还会带来细微字差，前面低温那段说的就是它。调采样，改的是怎么说；要它说得对，动的是前两步：材料给足，问题说明白。

## 回望与下一章

一次回答的来历：输入切成 token 装进上下文，模型给每个候选字打分，Softmax 换成份额，按份额抽样、接回、再来，直到停下。温度与 top-k、top-p 管抽样的口子；两次回答不一样，差异都发生在抽样这一步（低温下的细微字差另算，那是实现层的事）；它“忘了”与它“编了”，分别是上下文里没有那段内容、与“接一段像样的下文”这个训练目标的直接后果。

1. 同一个问题两次回答不一样，差异发生在哪一步，这一步的前后各是什么？
2. 把温度调高能让事实问答更准吗，温度管的到底是什么？
3. 换个会话模型就忘了说过什么，为什么这不算故障？

上下文是模型唯一能看到的东西。这句话的下一半是：装什么、怎么装，是使用者手里最大的一张牌。§0.4 讲这张牌怎么打，以及打出去之后怎么验收。
