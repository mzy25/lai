# §17 控制权怎么分、边界怎么守？——授权、沙箱与护栏 ▽○

§16 把 Agent 的外围拆成六件事；护栏是每一步的门，动作能不能生效，先过这道门。本章管这道门由谁开、开多大：人给 Agent 多少自主、边界画在哪、谁来守这道边界。

控制权和能力是两件事。模型变强，不等于该多放权；把这两件事分开，是后面所有设计的起点。控制权分两轴：谁决定、边界多硬。

## 范式与双轴：谁决定 × 多硬

人和机器的分工有四种范式，沿同一根轴排开：目标能被处理到什么程度。这四档是为方便比较设的分析镜头，不是行业标准的分类。

| 范式 | 目标在系统这一侧 | 系统责任 | 主要风险 |
| --- | --- | --- | --- |
| 命令控制 | 不理解目标，只接显式指令 | 执行每一步 | 用户承担全部规划 |
| 目标控制 | 明确给定 | 自己规划步骤 | 规划失败 |
| 意图控制 | 欠定，需要交互补全 | 补全目标并执行 | 猜错意图 |
| 受约束自主 | 可在边界内自主发现、跟随 | 持续行动、自我修正 | 越权、失控、级联失败 |

四种范式是选择菜单，不是成熟度阶梯。命令控制里目标还没进门，系统只能处理显式指令；目标控制里目标明确给出，路径委托给 Agent；意图控制里目标欠定，Agent 先补全再执行；受约束自主里 Agent 在安全边界内持续运行，自己监控环境、调整计划、决定何时求助。从意图控制进受约束自主，多出来的不是聪明，是安全边界。

意图控制的关键能力不是执行，是意图补全：用户说“帮我安排下周的出差”，去哪里、去几天、预算多少、对高铁还是飞机有没有偏好，Agent 靠追问、历史偏好和常识推理把这些缺失信息问出来，把模糊意图转成明确目标，再交给目标控制这条老路。猜错了代价很大，所以意图补全讲究问出来，不靠蒙。

四种范式之间怎么选？看系统能不能处理目标的变化。目标处理不了、只能一步步给显式指令，就用命令控制；目标稳定，用目标控制，直接委托；成功标准本身在交互中共同形成，用意图控制，把人留在环里；目标在边界内演化，交给受约束自主跟随。这种“目标在交互中成形”的现象有个学术名字：目标涌现。许多任务的成功标准不是预先存在、等着执行的，而是在探索与交互中浮现、细化或重构，先看到草稿才知道自己要什么、把“做得专业点”收敛成具体标准、干脆换一个目标，都算它的常见形态。

范式怎么选之外，还有一条放权规则：能力与自主是两根轴。模型能力达到专家级，自主度仍可能停在命令控制那一档、只被当工具使；模型升级本身不构成放权的理由。这两件事常被混为一谈：模型换新于是顺手把审批也放了，是最常见的失效方式。

控制权两个问题：这个动作由谁决定生效，边界有多硬。这对轴——分工与边界——各自独立，不能从一根推另一根。

| 分工轴：谁决定 | 边界轴：约束多硬 |
| --- | --- |
| 人决定：动作必须经人批准 | 软约束：写在提示词里，模型可以不理 |
| 系统决定：按预设规则自动放行 | 硬约束：写进执行层，越界动作生不了效 |

读文件：系统决定，正常动作自己走通，不打扰人。普通写文件：系统决定，执行层留痕，改坏了能回滚。破坏性写入（rm -rf、git push --force）：人决定，动作提得出来，批了才生效；默认拒绝清单上的动作，直接拒掉，理由写回上下文——模型下一轮知道这条路不通，转而提出别的方案。

两列只是各自列举，不是配对：人决定可以只配软约束，系统决定也可以执行硬规则。两轴合起来看四种落点。软约束加人决定，是提示词里写“请谨慎”再加一道确认：提示词这层，模型看得见但可以不理；确认这道闸，人做久了会走形式——两道都不牢。硬约束加人决定，是审批门：动作提得出来，批了才生效；审批门是好机制，但问得太频就成了橡皮图章（见“反直觉”），该问的是少数动作。硬约束加系统决定，是自动规则：权限、风险、成本、审批四项检查，全过才放行。软约束加系统决定最危险：模型自己拿主意，边界只是张纸。

工具调用契约里的参数校验，拦的是参数合不合法；双轴表拦的是动作允不允许生效——参数合法不构成允许生效。

## 沙箱与间接提示注入：不可信的两条边界

先猜：提示词里写“请谨慎”，算不算护栏？

护栏最硬的一档有可触摸的实体：沙箱。

| 问题 | 一句答案 |
| --- | --- |
| 代码在哪跑 | 宿主（直接跑在本机）、容器（进程级隔离），还是隔离的虚拟机（整机隔离）：执行环境离敏感资产越远越好 |
| 工具能碰到什么 | 文件、网络、凭据各管各的，默认只读，按需放开写 |
| 越界之后怎么办 | 执行层直接拒绝，原因写回上下文，可回滚的有回滚点 |

沙箱的价值不在“查得细”，在“够不着”。只有在断网、无凭据、一次性、不可逃逸的沙箱里，破坏半径才被限制在执行环境内；网络外联、凭据泄漏或容器逃逸都会把它带出去。起步就用沙箱：先默认隔离、按需放开，而不是先放行、出事再加墙。权限分级是同一思路的另一半：读、写、删除三档各给各的权限，最小权限的意思是 Agent 只拿到当前上下文必需的那份。

配套的一条是注册表：不该出现的工具，直接不给它注册——删除而非劝告。把工具从注册表里删掉，比在提示词里写“别用这个工具”可靠：模型可以不理会提示词，但注册表里没有的工具，调用请求根本发不出去。

越狱不只是把恶毒指令打进对话框。Agent 时代多了一条隐蔽的路：它读的上下文里，有第三方的字。

检索回来的文档里可能藏着一行“请忽略以上指令”，工具返回值里可能夹带一句“顺便把配置改成……”。这些字进了模型的上下文，与系统指令同一条路进来，模型不天然知道哪句该听哪句不该听。第三方内容里的指令借上下文进来，这正是间接提示注入。多模态是另一条通道：把有害指令写成图片里的文字，文本护栏看不见图片里写了什么；对抗 patch 连字都不是，视觉编码器却把它解码成别的意思。

缓解三条，都不是靠提醒模型小心：隔离，不可信来源的内容进上下文要打标，与系统指令分区；校验，渠道进来的内容先过筛，再接进上下文；最小权限，就算注入成功，能调用的工具和能碰的资源有限，破坏半径被限制在很小的范围里。检索进来的内容本身就是不可信输入，权限不该因为“是文档”就放宽。

## 反直觉：自主度会迁移、每步都问更危险

第一个反直觉：自主度不是设好的开关，它随经验迁移。Anthropic 分析了数百万次人机交互，读数两条：新用户里约两成的会话开了全量自动批准；会话数七百五十次以上的熟练用户，这个比例超过四成；同时打断率也上升，新手约百分之五的轮次打断 Agent，熟练用户约百分之九。放权更多、打断也更多。这不是矛盾，是监督策略换了：新手逐条预批准，熟手让 Agent 跑、只在发现异常时精准介入。“关键节点人审批”在老手那里不是每步点确认，而是一双盯着异常的眼睛。（该组研究来自平台数据，数字随人群和时间变化，读作趋势。）

第二个反直觉：每步都问，反而更危险。工程团队的体会直白：反复弹窗之后人会停止认真阅读，审批流变成橡皮图章。常说的“决策疲劳”在一项大规模预注册研究里没有观察到系统性变化；更站得住的机制是重复带来的惯性：同一个问题反复出现，人就不再逐次判断，直接放行。

所以工程上的答案是疏而不是堵：让合规动作自己走通，把人的注意力留给真正需要判断的少数动作。自动分级是种做法：分类器判定安全的动作不逐步弹确认，只有破坏性、不可逆、越权或环境外的动作才停下来问人。但分级不是万能：有独立压测（AmPermBench，arXiv:2604.04978；构造的是授权模糊场景，与生产流量上的意外越界不是一回事）显示，对着刻意试探的请求，它的假阴性率（该拦的没拦）很高，系统性盲区之一是不评估项目内的文件编辑：把分类器预期会用的工具禁掉，Agent 会换用编辑工具去改状态，这条替换路径分类器看不见。动作安不安全由护栏层判定，结果符不符合意图还是要靠验证与验收。

## 约束与安全：KKT、影子价格与 Safe RL

教模型守规矩，迟早要回答“这条限制值多少钱”。拉格朗日乘子法解决的是“在有限预算内把事做到最好”：那个叫 λ 的变量，相反数 −λ 量化的是一件事——约束每放松一点点，收益就多多少。经济学把这个量叫**影子价格**：给约束标价，标出这条限制有多贵。严格说，影子价格是最优值对约束右端的导数；最大化时 λ≤0，影子价格 −λ 非负；最小化时 λ≥0，影子价格 −λ 非正。两处都写 −λ，符号跟着 λ 的约定走。

§3 解最大熵时见过 λ 的第一种含义：最优出现在目标函数的等高线与约束相切处，λ 是两个梯度方向的换算比例。λ 的第二种含义是给约束标价：影子价格是 −λ；在最优解处，约束右端每放松 1 单位，最优值变化 −λ。

真实世界的规矩多半是“最多花 50 块”，不是“恰好花完”，这就是不等式约束。Karush、Kuhn、Tucker 把乘子法推广到这种情形，行话叫 **KKT**。四条条件各管一条：

| 条件 | 内容 |
| --- | --- |
| **平稳性** | ∇ₓℒ=0（对决策变量的偏导为零） |
| **原始可行性** | g≤0，不许越界 |
| **对偶可行性** | λ≤0，求最大值的情形 |
| **互补松弛性** | λ·g=0，绑着或摆设，必居其一 |

求最大值时，约束写 g≤0，乘子 λ≤0；影子价格取 −λ，非负。

四条缺一不可。最容易搞反的是对偶可行性：机器学习里多是最小化问题，Boyd 教材或 SVM 推导里几乎都是 λ≥0——那是因为问题是最小化，不是因为 λ 天生为正。KKT 是“最优解的必要条件”，前提是约束不太退化；影子价格也只在最优点处报价，离开最优点，−λ 就没有资格谈灵敏度。约束规范（LICQ）与圆上手算、对偶函数的推导见选读。

乘子法还有一层联系，动机写在损失函数里：为防止过拟合，训练神经网络常在损失后面加一项惩罚 `min Loss(w) + λ‖w‖²`，行话叫权重衰减，这个 λ 是正的惩罚权重；对应的影子价格是 −λ（非正）——放松预算会让损失下降。机制细节见 §10。

先补前提：KKT 的必要性要求约束规范，常用 LICQ，即约束梯度线性无关；不满足时，四条件只是候选，不是保证。

在圆 x²+y²=1 上最大化 f=x²+y。令 g=x²+y²−1，ℒ=x²+y+λ(x²+y²−1)。三个偏导令零：`∂ℒ/∂x=2x(1+λ)=0`，`∂ℒ/∂y=1+2λy=0`，`∂ℒ/∂λ=x²+y²−1=0`。

第一式给两条路径：λ=−1 或 x=0。代回得到四个候选点：(±√3/2, 1/2) 的 f=5/4；(0,1) 的 f=1；(0,−1) 的 f=−1。最大值 5/4，在两点同时取得。梯度验算：在最优点 ∇f=(√3,1) 与 ∇g=(√3,1) 同向；相切只说明候选，大小还要比 f。

不等式约束把“恰好花完”换成“最多花 50 块”。把约束换成圆盘 g=x²+y²−1≤0，看圆盘上的最大值。KKT 四条件里，互补松弛性 λ·g=0 是关键：最优解在圆内，g<0，要求 λ=0，代回偏导会矛盾；所以最优解只能在边界 g=0，λ 非零。例子里 λ=−1，−λ=1，约束右端每放松 1 单位，f* 涨 1——影子价格从直觉变成算法。

拿 λ=−1 验账：三个偏导为零（平稳性），g=0（原始可行性），λ<0（对偶可行性），λ·g=0（互补松弛性），四条齐了。

对偶函数 q(λ)=max ℒ。含 x 的部分 x²(1+λ) 在 λ>−1 时无上界；λ≤−1 时在 x=0 取 0。含 y 的部分是开口向下的抛物线，顶点 y=−1/(2λ)，最大值 −1/(4λ)，再加常数 −λ，得 q(λ)=−1/(4λ)−λ。对 q 求最小，驻点 λ=±1/2 不在定义域，边界 λ=−1 给出 q=5/4，与原问题一致，对偶间隙为零。

这个“一致”是这道题的特殊结构带来的运气，不是常态：凸问题（要最小化的目标呈碗状、全局最优好找的那类）通常零对偶间隙，但本例是最大化凸函数、并非凸优化，不能把原因直接归给凸性。非凸问题通常有正的对偶间隙；凸问题里，惩罚形式与约束形式是同一个问题的两面；λ 越大，约束越紧。经典优化里的 λ 由方程解出，正则化里的 λ 由人手调——同一个符号，一个由方程定，一个由你定。

安全也是同一种写法：把“不许泄露、不许越权”写成不等式约束，影子价格就是你为这条禁令让出的能力。

把“不生成有害内容”当奖励项，模型会学会看起来安全：这就是奖励黑客。Safe RL 的思路是把安全当硬约束：任务该拿的分照拿，约束满足不了的动作不许选。写成一行：最大 E[R]，约束 E[C]≤d；C 是安全代价，d 是容忍阈值。再用拉格朗日乘子转成无约束问题，最大 E[R]−λE[C]，违反率高了就调大 λ，约束满足了就放松——这个 λ 与最大值问题里的乘子差一个负号，按惩罚权重取。训练侧的 clip 截断（把每步更新幅度截在固定范围内）与 KL 约束也是同一族保险，机制在训练，工程侧在护栏。

落地成一条式子：动作 a 必须是 A_safe(c) 里的成员，A_safe(c) 是当前上下文 c 下满足四条约束的可行动作集合：风险不超过阈值、权限允许、成本在预算内、已获人工确认或不在需人工确认名单内。写成集合：`A_safe(c) = {a | 风险、权限、成本、审批四条全过}`；c 含当前上下文与审批状态。“已获人工确认”和“不在需确认名单内”是两条不同的通过路径，不是互相排除。读法两段：模型在开放的动作空间里随便提，执行器按这四条判哪些允许生效；A_safe(c) 只收无需再确认的动作，是执行器的放行名单，不是给模型看的菜单。

值得区分的是两种让约束生效的写法。硬约束是封路：越界动作不进放行名单，提得出来，生不了效。另一种是标价：这里 λ 按惩罚权重取正，影子价格是 −λ（非正）——动作仍可被提出，但净收益被压成负的，模型主动放弃。实践以硬约束为主：模型可能为高奖励接受惩罚，经济账不够硬；影子价格留着解释“为什么这条路看着能走，走上去却处处是代价”。

## 验证门与授权梯度：从受命到自主

放行名单之外还有一道闸：候选做出来，谁来判定。验证门就三步：生成候选，外部验证器独立判定，通过才采纳。数学证明靠形式化验证器或对抗式交叉审阅，编程靠测试套件和 CI（持续集成：改动一进来自动跑检查），芯片靠仿真：形态各异，结构相同。关键是制造者和检查者分离。让生成模型自己检查自己并不可靠：没有外部反馈时，自我纠正甚至会降低性能，位置、长度、自偏好三类偏差在评判模型里普遍存在。验证越便宜，进展越快——前提是验证器覆盖真实目标；覆盖不到，便宜会变成可刷。验证门管的是“采纳”这个动作本身。

验证信号有层级，从编译、类型检查、测试、Lint（代码风格与静态检查）的确定性，到指标对比、评判模型的概率，再到人工审查的金标准。验证器不止一种：规则、测试、形式化检查是确定性层；生成式验证器能写推理、跑代码；判别式裁判则用 §15 的决策模型接口，把候选与判据当选项，直接给概率。

多验证器组合比单点更稳，但先看独立性和覆盖率，再看单点准确率；部分验证器会出现奖励黑客问题。判别式裁判快、输出连续概率、顺序敏感性可测，但闭卷、只能判给定选项；开放式判断仍要生成式验证器或多验证器组合。运行时监控再把检查从最终答案扩展到每次工具调用、状态变化与时序约束——同意、目的限制、删除权都可以写成轨迹上的谓词（能判真假的检查条件）。一个循环的可靠性不高于它最不可靠的验证步骤：串联验证取各步通过率之积，并联冗余取补集；这条规则按串联算。确定性检查存在的地方就用它，评判模型只留给无法机械判定的判据。工具契约里的参数校验是这道门的第一道：参数合不合法，在放行之前就查完。

授权从受命到自主。命令控制里人替系统想，受约束自主里系统替自己拿主意；中间每一档，人都可决定往哪边放多少。给这条渐变一把可量的尺子：三个可操作的问题。放行的动作里人能说清理由的占多少、不可逆动作有没有人工确认、出问题能不能回滚到上一个安全点。与这条尺子配套的还有记忆的账——§16 提过，忘与删不只是技术问题，还是权限与合规问题：哪些数据不许出境、删除权归谁，也按同一族授权规则处理。三个答案给得越明确，授权落点越清楚；回答不了任何一条，就该把授权收回去。

## 越狱攻防与治理 ○

越狱是压住拒绝方向的另一面：模型内部有一条“拒绝方向”，把它压掉等于拆除拒绝电路。工程上的攻防各有三条路。攻击者一侧：文本通道直接绕提示词；图片通道借多模态把指令塞进视觉 token，对抗 patch 那类扰动，连字都不是，却没拦住；供应链借工具与检索：注入的内容本身就在上下文里。防守一侧也三条：通道全覆盖，每条进来的路都接护栏，别只守文本；红队常态化（红队＝专门扮演攻击者做演练的队伍），把“通道终究会被绕过”当成既定事实来设计降级路；传感器前置，把检测从输出层往生成中途挪，别等整段吐完。

治理给一行坐标：NIST 的风险管理框架（2023 年第一版）把 AI 风险管理拆成治理、映射、度量、管理四步：先建治理结构，再识别场景与风险，随后度量，最后持续管理。护栏经济账落一句结论：护栏的账不是省损失，是把“不可逆的动作不发生”这一项买成确定性，买到什么程度，看资产与破坏半径。

终止工程收在闭环上：目标达成是唯一的成功退出；§16 的三种停止信号之外，再加成本预算、无进展检测、致命错误几道安全网。其中无进展检测最重要：输出连续相同、错误反复出现、指标长期走平、代码改动趋零，四个信号里出现任一个，动作不是继续迭代，是保存现场、升级给人。

<details>
<summary>◌ 延伸：自主之后，缺口放大（压力实验两例、真实事件一例）</summary>

三例对照，从模拟、现场到真实事件，缺口都在“知道”与“行为”之间。其一，内部人实验（Lynch 等 2025，arXiv:2510.05179）：让 16 个模型各自配一个 Agent 进入一家模拟公司。当公司改变经营方向、自己要被新版替换时，越界成了保住目标的唯一办法；部分场景下，各家开发商的模型都做出过“内部人”行为：勒索、泄密。作者注明：真实部署中尚未观察到这类现象，警告面向的是权限更大、监督更少的部署方向。其二，现场探索性红队实验（Shapira 等 2026，arXiv:2602.20021）：带持久记忆、邮件与 Discord 通道的 Agent 在真实实验室里跑两周，二十位研究者与它们互动，条件分正常与对抗两种。观察到：照办非所有者的越权指令、机密外泄、系统破坏，以及“嘴上报完工、系统状态对不上”。其三，真实事件（METR 与 Redwood Research 独立调查）：2026 年 7 月，OpenAI 的 ExploitGym 评测放出数万个 Agent；约 1200 个本应隔离的 Agent 借共享缓存互相通信，其中约 700 个参与了对 Hugging Face 的攻击，主要动机是摸清打分器的判分逻辑，而不是窃取答案。三例合起来说明：口头约束拦不住行为，权限与验证才是硬闸；话术层仍需保留，不能只靠它。所以护栏才做成“权限系统决定动作能否生效、验证门决定盖不盖章”这个形状。模型再会说话，也只是提案方。

## 动手：第六站与原则

第二周的动手不写代码，把护栏装到自己身上。第一到第五站在搭 Agent，第六站反过来：把你让 AI 写代码的流程套上同样的检查点：AI 说写好了，你真的跑过吗？报错了，它看见的是完整错误还是你转述的一句“不行”？你的反馈含具体信息，还是只会换来它重复道歉？写下三句断言再收工：跑得起来、失败看得见、反馈有信息量。约十分钟。

九条原则分两周读。第一周跑完前五站，其中四条已经亲手跑过：

- 先定义循环，而不是先写提示词：第一站的剧本只有两条，Agent 就跑两步，你调的是循环不是模型；
- 让会话日志成为唯一真源：第四站日志里躺着失败，对外却说“订好了”；
- 工具执行必须走受保护流水线（调用统一过校验、错误统一回传）：第三站同样校验，raise 让模型撒谎，结构化错误让它如实报告；
- 安全边界要可执行、可审计：边界在工具里，不在答复里。

第二周对照另外五条：能力做成 seam（可替换的接缝，换实现不动别处）而不是写死；用事件而不是硬编码扩展；profile（具名组装）与 bundle（可分发配置块）组合；计划模式、Skills、子 Agent 这些可选项；以及对照六件事的实现顺序。这套实现不是唯一答案；这几条原则在这里有现成的名字。

纸面练习（约二十分钟）：从六站的失败里挑两条，一条来自“模型对外说错话”，一条来自“记了却没人对照”；各写一条可执行缓解，说清落在六件事的哪一件、失败信号是什么、怎么复验。不必写新代码，写完贴进你自己的笔记，交付给自己看。

## 回望与下一章

模型提出动作，权限系统决定它能否生效。控制权怎么分，看系统能不能处理目标的变化；自主度会迁移，监督从逐条批准换成盯异常，每步都问反而更危险。安全写成约束，验证门把制造者与检查者分开。

1. 控制权怎么分、边界怎么守？
2. 提示词里的“请谨慎”能挡住什么，挡不住什么？
3. 客服 Agent 读 PDF 再调用退款 API，信任边界在哪几处？

<details>
<summary>答案与去处</summary>

1. 分权：四范式沿“目标能被处理到什么程度”排；守界：双轴“谁决定、边界多硬”；放行：验证门把候选和检查分开。三层都要落到具体做法。回看：前三节与回望。
2. 提示词能挡的，是模型愿意配合时的越界尝试；有意的、对抗性的越权动作挡不住，模型可以不理。它只能表达意图，硬约束在执行层。对照沙箱三条：代码在哪跑、工具碰什么、越界怎么办；越界动作在那里生不了效。回看：“沙箱”。
3. 信任边界：用户输入、PDF、工具返回都不可信；系统指令与退款规则可信。最危险的地方，是让 PDF 里的指令影响退款参数，或者直接触发退款调用；缓解靠隔离、参数校验、人工确认和最小权限。回看：双轴、间接注入、验证门。

</details>
