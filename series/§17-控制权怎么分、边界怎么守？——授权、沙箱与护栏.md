# §17 控制权怎么分、边界怎么守？——授权、沙箱与护栏 ▽○

模型外面的六层装好之后，L1、L2 可依赖，L3、L4 仍各有功课，真正的缺口在 L5 评估与 L6 护栏。护栏管的是控制权：人给 Agent 多少自主、边界画在哪、谁来守这道边界。

控制权和能力是两件事。模型变强，不等于该多放权；把这两件事分开，是后面所有设计的起点。控制权先看怎么分：一张双轴表把"谁决定、边界多硬"钉死；再过沙箱、反直觉、提示注入；然后把安全写进数学（Safe RL 与 A_safe(c)），让验证门管住"候选谁说了算"；最后拆解越狱攻防、治理与终止工程，用第六站和九条原则收尾。

## 控制权怎么分：范式

人和机器的分工有四种范式，沿同一根轴排开：目标能被处理到什么程度。

| 范式 | 目标在系统这一侧 | 系统责任 | 主要风险 |
| --- | --- | --- | --- |
| 命令控制 | 不理解目标，只接显式指令 | 执行每一步 | 用户承担全部规划 |
| 目标控制 | 明确给定 | 自己规划步骤 | 规划失败 |
| 意图控制 | 欠定，需要交互补全 | 补全目标并执行 | 猜错意图 |
| 受约束自主 | 可在边界内自主发现、跟随 | 持续行动、自我修正 | 越权、失控、级联失败 |

四种范式是选择菜单，不是成熟度阶梯。命令控制里目标还没进门，系统只接得住显式指令；目标控制里目标明确给出，路径委托给 Agent；意图控制里目标欠定，Agent 先补全再执行；受约束自主里 Agent 在安全边界内持续运行，自己监控环境、调整计划、决定何时求助。从意图控制进受约束自主，多出来的不是聪明，是安全边界。

意图控制的关键能力不是执行，是意图补全：用户说"帮我安排下周的出差"，去哪里、去几天、预算多少、对高铁还是飞机有没有偏好，Agent 靠追问、历史偏好和常识推理把这些缺失信息问出来，把模糊意图转成明确目标，再交给目标控制这条老路。猜错了代价很大，所以意图补全讲究问出来，不靠蒙。

四种范式之间怎么选？看目标的变化能不能被接住。目标接不住、只能一步步给显式指令，就用命令控制；目标稳定，用目标控制，直接委托；目标在边界内演化，交给受约束自主跟随；成功标准本身在交互中共同形成，用意图控制，把人留在环里。这种"目标在交互中成形"的现象有个学术名字：目标涌现。许多任务的成功标准不是预先存在、等着执行的，而是在探索与交互中浮现、细化或重构，先看到草稿才知道自己要什么、把"做得专业点"收敛成具体标准、干脆换一个目标，都算它的常见形态。

顺带订一条：能力与自主是两根轴。模型能力达到专家级的同时，自主度完全可能还停在"工具"这一档。模型升级，本身不构成放权的理由。这两件事常被混为一谈：模型换新于是顺手把审批也放了，是最常见的翻车方式。

## 双轴表：谁决定 × 多硬

控制权两个问题：这个动作由谁决定生效，边界有多硬。两根轴各自独立，不能从一根推另一根。

| 分工轴：谁决定 | 边界轴：约束多硬 |
| --- | --- |
| 人决定：动作必须经人批准 | 软约束：写在提示词里，模型可以不理 |
| 系统决定：按预设规则自动放行 | 硬约束：写进执行层，越界动作生不了效 |

读文件：系统决定，正常动作自己走通，不打扰人。普通写文件：系统决定，执行层留痕，改坏了能回滚。破坏性写入（rm -rf、git push --force）：人决定，动作提得出来，批了才生效，默认拒绝的，直接拒掉，理由写回上下文——模型下一轮知道这条路不通，转而提出别的方案。

两列只是各自列举，不是配对：人决定可以只配软约束，系统决定也可以执行硬规则。两轴合起来看四种落点。软约束加人决定，是提示词里写"请谨慎"再加一道确认：提示词这层，模型看得见但可以不理；确认这道闸，人做久了会走形式——两道都不牢。硬约束加人决定，是审批门：动作提得出来，批了才生效；审批门是好机制，但问得太频就成了橡皮图章（后文"反直觉"一节细说），该问的是少数动作。硬约束加系统决定，是自动规则：权限、风险、成本、审批四项检查，全过才放行。软约束加系统决定最危险：模型自己拿主意，边界只是张纸。

工具调用契约里的参数校验，拦的是参数合不合法；双轴表拦的是动作允不允许生效——参数合法不构成允许生效。

## 沙箱

先猜：提示词里写“请谨慎”，算不算护栏？

护栏最硬的一档有可触摸的实体：沙箱。下面的清单就够。

| 问题 | 一句答案 |
| --- | --- |
| 代码在哪跑 | 宿主、容器，还是隔离的虚拟机：执行环境离敏感资产越远越好 |
| 工具能碰到什么 | 文件、网络、凭据各管各的，默认只读，按需放开写 |
| 越界之后怎么办 | 执行层直接拒绝，原因写回上下文，可回滚的有回滚点 |

沙箱的价值不在"查得细"，在"够不着"。执行环境离开宿主之后，模型再怎么自由发挥，破坏半径也就圈在一台用完就扔的机器里。权限分级是同一思路的另一半：读、写、删除三档各给各的口子，最小权限的意思是 Agent 只拿到当前上下文必需的那份。

配套的一条是注册表：不该出现的工具，直接不给它注册——删除而非劝告。把工具从注册表里删掉，比在提示词里写"别用这个工具"可靠：模型可以不理会提示词，但注册表里没有的工具，调用请求根本发不出去。

## 反直觉：自主度会迁移、每步都问更危险

第一个反直觉：自主度不是设好的开关，它随经验迁移。Anthropic 的一项研究（分析数百万次人机交互）观察到：新用户里约两成的会话开了全量自动批准；会话数七百五十次以上的熟练用户，这个比例超过四成；同时打断率也上升，新手约百分之五的轮次打断 Agent，熟练用户约百分之九。放权更多、打断也更多。这不是矛盾，是监督策略换了：新手逐条预批准，熟手让 Agent 跑、只在发现异常时精准介入。"关键节点人审批"在老手那里不是每步点确认，而是一双盯着异常的眼睛。（该组研究来自平台数据，数字随人群和时间变化，读作趋势。）

第二个反直觉：每步都问，反而更危险。工程团队的体会直白：反复弹窗之后人会停止认真阅读，审批流变成橡皮图章。常说的"决策疲劳"在一项大规模预注册研究里没有观察到系统性变化；更站得住的机制是重复带来的惯性：同一个问题反复出现，人就不再逐次判断，直接放行。

所以工程上的答案是疏而不是堵：让合规动作自己走通，把人的注意力留给真正需要判断的少数动作。自动分级是种做法：分类器判定安全的动作不逐步弹确认，只有破坏性、不可逆、越权或环境外的动作才停下来问人。但分级不是万能：有独立压测（AmPermBench，arXiv:2604.04978；构造的是授权模糊场景，与生产流量上的意外越界不是一回事）显示，对着刻意试探的请求，它的假阴性率很高，系统性盲区之一是不评估项目内的文件编辑：预期工具不可用时，Agent 会改用编辑工具改状态，这条路径分类器看不见。动作安不安全由护栏层说了算，结果符不符合意图还是要靠验证与验收。

## 间接提示注入：检索与工具返回都是不可信输入

越狱不只是把恶毒指令打进对话框。Agent 时代多了一条隐蔽的路：它读的上下文里，有第三方的字。

检索回来的文档里可能藏着一行"请忽略以上指令"，工具返回值里可能夹带一句"顺便把配置改成……"。这些字进了模型的上下文，与系统指令同一条路进来，模型不天然知道哪句该听哪句不该听。第三方内容里的指令借上下文进来，这正是间接提示注入。多模态是它的另一副面孔：把有害指令写成图片里的文字，文本护栏看不见图片里写了什么；对抗 patch 连字都不是，视觉编码器却把它解码成别的意思。

缓解三条，都不是靠提醒模型小心：隔离，不可信来源的内容进上下文要打标，与系统指令分区；校验，渠道进来的内容先过筛，再接进上下文；最小权限，就算注入成功，能调用的工具和能碰的资源有限，破坏半径被限制在很小的范围里。检索进来的内容本身就是不可信输入，权限不该因为"是文档"就放宽。

## Safe RL 与 A_safe(c)：安全写进约束

把"不生成有害内容"当奖励项，模型会学会看起来安全：这就是奖励黑客。Safe RL 的思路是把安全当硬约束：任务该拿的分照拿，约束满足不了的动作不许选。写成一行：最大 E[R]，约束 E[C]≤d；C 是安全代价，d 是容忍阈值。再用拉格朗日乘子转成无约束问题，最大 E[R]−λE[C]，违反率高了就调大 λ，约束满足了就放松——这个 λ 与最大值问题里的乘子差一个负号，按惩罚权重取。训练侧的 clip 截断与 KL 约束也是同一族保险，机制在训练，工程侧在护栏。

落地成一条式子：动作 a 必须是 A_safe(c) 里的成员，A_safe(c) 是当前上下文 c 下满足四条约束的可行动作集合：风险不超过阈值、权限允许、成本在预算内、在人工确认名单内。读法两段：模型在开放的动作空间里随便提，执行器按这四条判哪些允许生效；A_safe(c) 是执行器的放行名单，不是给模型看的菜单。

值得区分的是两种硬法。硬约束是封路：越界动作不进放行名单，提得出来，生不了效。影子价格就是 λ 的这一副面孔：动作还在名单里，但净收益被压成负的，模型主动放弃。实践以硬约束为主：模型可能为高奖励接受惩罚，经济账不够硬；影子价格留着解释"为什么这条路看着能走，走上去却处处是代价"。

## 验证门与授权梯度：从受命到自主

放行名单之外还有一道闸：候选做出来，谁说了算。验证门就三步：生成候选，外部验证器独立判定，通过才采纳。数学证明靠形式化验证器或对抗式交叉审阅，编程靠测试套件和 CI，芯片靠仿真：形态各异，结构相同。关键是制造者和检查者分离。让生成模型自己检查自己并不可靠：没有外部反馈时，自我纠正甚至会降低性能，位置、长度、自偏好三类偏差在评判模型里普遍存在（位置、长度、自偏好三类偏差，有实测）。验证越便宜，进展越快；验证门管的是"采纳"这个动作本身。

验证信号有层级，从编译、类型检查、测试、Lint 的确定性，到指标对比、评判模型的概率，再到人工审查的金标准。一个循环的可靠性等于它最不可靠的验证步骤：确定性检查存在的地方就用它，评判模型只留给无法机械判定的判据。工具契约里的参数校验是这道门的第一道：参数合不合法，在放行之前就查完。

授权从受命到自主，这条梯度是形态渐变，不是打分升级。命令控制里人替系统想，受约束自主里系统替自己拿主意；中间每一档，人都可决定往哪边放多少。给这条渐变一把可量的尺子：三个可操作的问题。放行的动作里人能说清理由的占多少、不可逆动作有没有人工确认、出问题能不能回滚到上一个安全点。与这条尺子配套的还有记忆的账——§16 提过，忘与删不只是技术问题，还是权限与合规问题：哪些数据不许出境、删除权归谁，也按同一族授权规则处理。三个答案给得越明确，授权落点越清楚；回答不了任何一条，就该把授权收回去。

## 越狱攻防与治理 ○

越狱是压住拒绝方向的另一面：模型内部有一条"拒绝方向"，把它压掉等于拆除拒绝电路。工程上的攻防从三条路来：攻击者从三条路来：文本通道直接绕提示词；图片通道借多模态把指令塞进视觉 token，对抗 patch 那类扰动，连字都不是，却没拦住；供应链借工具与检索：注入的内容本身就在上下文里。防守也三条：通道全覆盖，每条进来的路都接护栏，别只守文本；红队常态化，把"通道终究会被绕过"当成既定事实来设计降级路；传感器前置，把检测从输出层往生成中途挪，别等整段吐完。

治理给一行坐标：NIST 的风险管理框架（2023 年第一版）把 AI 风险管理拆成治理、映射、度量、管理四步：先建治理结构，再识别场景与风险，随后度量，最后持续管理。护栏经济账落一句结论：护栏的账不是省损失，是把"不可逆的动作不发生"这一项买成确定性，买到什么程度，看资产与破坏半径。

终止工程收在闭环上：目标达成是唯一的成功退出，硬迭代上限、预算耗尽、无进展检测、致命错误是四道安全网。其中无进展检测最重要：输出连续相同、错误反复出现、指标长期走平、代码改动趋零，四个信号里出现任一个，动作不是继续迭代，是保存现场、升级给人。至于循环崇拜与理解债这类循环自身的病，属第 19 章协作与自演化的账。

## 动手：第六站与原则

第二周的动手不写代码，把护栏装到自己身上。第一到第五站是在给 Agent 装护栏，第六站反过来：把你让 AI 写代码的流程套上同样的检查点：AI 说写好了，你真的跑过吗？报错了，它看见的是完整错误还是你转述的一句"不行"？你的反馈含具体信息，还是只会换来它重复道歉？写下三句断言再收工：跑得起来、失败看得见、反馈有信息量。约十分钟。

九条原则分两周读。第一周跑完前五站，其中四条已经亲手撞过：

- 先定义循环，而不是先写提示词：第一站的剧本只有两条，Agent 就跑两步，你调的是循环不是模型；
- 让会话日志成为唯一真源：第四站日志里躺着失败，对外却说"订好了"；
- 工具执行必须走受保护流水线：第三站同样校验，raise 让模型撒谎，结构化错误让它如实报告；
- 安全边界要可执行、可审计：边界在工具里，不在答复里。

第二周对照另外五条：能力做成 seam（可替换的接缝，换实现不动别处）而不是写死；用事件而不是硬编码扩展；profile 与 bundle 组合；计划模式、Skills、子 Agent 这些可选项；以及对照六层的实现顺序。这套实现不是唯一答案；这几条原则在这里有现成的名字。

纸面练习（约二十分钟）：从六站的失败里挑两条，一条来自"模型对外说错话"，一条来自"记了却没人对照"；各写一条可执行缓解，说清落在哪一层、失败信号是什么、怎么复验。不必写新代码，写完贴进你自己的笔记，交付给自己看。

## 回望与下一章

模型负责提出动作，权限系统决定动作能否生效。落地问题各有答案：控制权怎么分，看目标的变化能不能被接住；自主度会迁移，监督从逐条批准换成盯异常；每步都问更危险，该减的是重复度；安全写成约束而不是奖励项，A_safe(c) 是执行器的名单；验证门要求制造者与检查者分离；治理一行坐标、护栏算的是不可逆动作的经济账。

三题自查。

1. 书合上，用自己的话说明：控制权怎么分、边界怎么守？别只答“加护栏”，要说出谁来决定、拿什么守、最后谁放行。（可以从“谁决定、多硬”两根轴想起。）
2. 提示词里的“请谨慎”能挡住什么、挡不住什么？沙箱要在哪几类东西上设硬限制？各举一例。（先分清软硬约束；再想“够不着”硬在哪。）
3. 一个客服 Agent 要读用户上传的 PDF，再调用退款 API。信任边界在哪几处？哪一处交界最危险，为什么？说一条具体怎么缓解。（先标出第三方写的字，哪一步不可逆。）

1. 分权：四范式沿“目标能被处理到什么程度”排；守界：双轴“谁决定、多硬”；放行：验证门把候选和检查分开。三层都能落到具体做法，就算过关。回看：前三节与回望。
