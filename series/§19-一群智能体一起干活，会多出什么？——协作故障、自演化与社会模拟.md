# §19 一群智能体一起干活，会多出什么？——协作故障、自演化与社会模拟 ▽◇

上一章末尾留了个问题：一群智能体一起干活，会多出什么？答案分三层：协作，看一群智能体一起上会多出哪些翻车方式；自演化，看人工搭的部件能不能自己长、自己换；社会模拟，把这样一群智能体放进模拟环境，让它们过日子，看会不会长出"社会现象"。

协作不制造能力，只放大缺口：好的分工把复杂度拆开，坏的分工把单点故障接成网络。自演化能跑，但有三条硬边界把"全自动"划掉：当前稳定的做法是让系统出候选、人类做策展。社会模拟把这两层放进一个可重复的实验环境，先看现象，再谈判断。

## 甲部：分工的代价

### 五种拓扑，只用三种

一个 Agent 是一个循环；多个 Agent 就是把五样东西在 n 个循环之间重新展开一遍：动作空间、观测空间、状态、评估、护栏，每一样都要重新定义。行业实践收敛出五种编排拓扑（谁连着谁、谁指挥谁的结构），按任务特征选，不按数量堆：

| 拓扑 | 结构 | 关键失效 |
| --- | --- | --- |
| Supervisor | 中央协调器把任务委派给专业子 Agent | 主上下文被子 Agent 的中间结果淹没 |
| Pipeline | 顺序链，上一环输出是下一环输入 | 上游错误沿管道放大，越走越远 |
| Fan-out | 并行分发，末尾聚合 | 聚合环节缺一致性校验，结论互相打架 |
| Debate | 多模型并行再加一个裁决模型 | 同底座、相似提示，错得一致；裁决只盖章 |
| Swarm | 动态对等 Agent 群体 | 全局预算失控，成本几何级数涨 |

常用的是前三种：Supervisor 管最常见的分工，Pipeline 用于走查（动手节要用），Fan-out 管并行聚合。Debate 的问题：多个模型互相辩论听着稳妥，但常基于同一个底座，看错时错在同一个方向，裁决模型只把它盖章通过。Swarm 的账在预算：参与者越多，协调开销越大，成本涨得比能力快。

比横向分工更常见的结构是纵向分层：把任务按抽象层次切开，高层定战略并验收、中层分解、下层执行。这不是第六种拓扑，是可以叠在任意横向拓扑上的结构。每层只管自己时间尺度内的事；代价在层间接口：目标怎么分解、结果怎么回传、异常怎么升级，这三样必须显式定义，否则信息在层间丢失。

### AgentFail：失败根因离出错的地方可以很远

多 Agent 失败不是单点故障的简单叠加。AgentFail 是这方面少见的实证研究：307 个来自两个低代码编排平台、覆盖十套工作流的真实失败日志。它把失败根因按抽象层级归并成三层十六类：节点级（单个 Agent 内部的问题，7 类）、结构级（工作流拓扑的问题，7 类）、平台级（底层运行时，2 类）。编号按层内顺序排，走查时就按这套编号指认。

三层十六类按层排，走查时按这套编号指认：

| 层 | 十六类 |
| --- | --- |
| 节点级（7 类） | 工具/动作规划错误、响应格式错误、响应内容偏差、知识/推理局限、提示词设计缺陷、语言/编码缺陷、工具调用/知识库检索错误 |
| 结构级（7 类） | 输入校验缺失、节点依赖不合理、循环/死锁、条件判断错误、任务分解不当、上下文冲突、跨 Agent 工具/接口不匹配 |
| 平台级（2 类） | 网络/资源波动、服务不可用 |

关键发现是：失败根因和暴露位置可以隔得很远。看一个三节点文档流水线：A 做 OCR 提取，B 翻译，C 写摘要。A 把原文"2024"读成"2021"：根因在 A；B 忠实翻译了错误数据，缺一道输入校验；C 输出的摘要到了用户眼前：错误在这里才暴露。用户在 C 处发现问题，根因却在两跳之外的 A。如果只在 C 端加"输出检查"，永远抓不住这类错误：C 的摘要逻辑本身没问题。

四个可操作的结论比研究里的数字更值得记。其一，跨层部署：护栏要在节点、结构、平台三层同时设防，缺一层就在那一层反复翻车；第 17 章的双轴表在协作网上按三层摊开。其二，修复策略里成功率最高的是输入校验前置：把校验放在错误还没传播出去的位置，而不是在暴露点补救。其三，分层归位：各层的问题各层修，不串层。其四，照瓶颈放投入：标注研究（MAST）指出，多 Agent 的瓶颈在协调与验证，而不是单点能力。

### 上下文隔离：子 Agent 的正当理由

除了分工，多 Agent 还有一个常被忽略的正当理由：上下文隔离。每步都要动态组装上下文，长任务里无关信息会拖低推理质量。把一段不需要主 Agent 完整历史的推理派给子 Agent，主 Agent 只保留任务图谱和结构化摘要。这是注意力预算管理，不是炫技（留什么归第 16 章的三级台阶管，这里只管给谁看）。判据一句话：一段推理不需要全部历史，就派出去。

隔离也有代价。交接处正是第 17 章说的间接提示注入的暴露面：检索内容和工具返回是不可信输入，到了多 Agent 里，一条被做过手脚的消息会沿链路一路传播，谁都以为上游校验过了。所以跨交接的内容要打标、要校验、要给最小权限。隔离解决"不该看的不给看"，不解决"给看的没被做过手脚"。

### 人在回路：一等节点，不是过渡

人类在多 Agent 图上是特殊节点：极高延迟、极低带宽，却是最终责任承担者。不可逆动作和低置信度分支的最终决策权，必须留在人手里。生产模式收敛为四种：高风险操作前中断等批准；AI 草稿停下来人工审阅；工具调用内拦截审查；循环里反复询问直到输入合规。

但"每步都问"会把审批流变成橡皮图章（§17 讲过）。真正要外置的是触发条件：置信度低于阈值、动作在敏感清单上、连续失败超过设定次数。这些条件写进系统规则，不靠模型自觉。人不是被替代，而是被画进工作流图里：可寻址、可中断、可回溯的一等节点。

甲部收一句：协作系统的强度，是各节点强度的连乘，恒低于最薄弱的那一环。节点越多，乘进去的小于 1 的因子越多。这不是悲观，是设计约束：先想清楚最弱一环在哪，再决定要不要协作。协作放大缺口，不制造能力。循环自身也有两笔账——循环崇拜与理解债：把"转起来了"当成"做对了"，把没写进说明的默契当成不需要写。循环不替代工程能力。

## 乙部：让系统自己长

### 三条路线，一个闭环

外部系统在模型外面，不锁在权重里，就能像代码一样被改、被换、被迭代。自演化研究收敛出三条路线，各改一层东西。Skill 演化改技能库：从失败轨迹蒸馏可复用策略写回去（第 18 章说过技能包的构造，这里说它怎么长）。Workflow 演化改流程拓扑：把工作流建成代码图，用搜索算法自动优化。协作拓扑演化改通信结构：把多 Agent 图交给优化器，节点换提示词、边换连接。三条路线之外，更激进的一支是自改代码：让 Agent 改自己的代码库，逐版实测验证、择优存档。改的仍是外部系统，不是运行时权重。

三条路线共享同一个闭环：生成候选、环境反馈打分、优胜者写回库、下一轮基于新库继续。要学的不是权重，是模型外面的整个 Harness。用 §7 的话说：自演化，就是把外环也交给系统自己转——原来人在外面调的那一圈，现在开始轮到系统自己调。两环同转容易失稳；怎么守，§11 那块深挖里有三条现成的稳定器。

### 三条硬边界

这个闭环不是无限的。第一条边界叫 Library Drift：技能库无节制增长会退化（arXiv:2605.19576）。有对照研究（SkillsBench，arXiv:2602.12670）给出结果：无治理的自主生成技能，平均收益约零个百分点；有人工策展的，约 +16 个百分点。差距不在"谁生成的内容差"，在生命周期治理：没有基于结果的淘汰、没有容量上限、没有元技能授权先验，库会越用越差，直到把优质条目也淹进噪声。反过来，带治理的演化方向相反：有工作把成功轨迹固化成技能模板、失效自动重编译，一百五十轮纵向评测里成功率从 87% 升到 91%，无治理对照则往下。

第二条边界来自数学：容量无界的自我修改，会把原本可学的任务变成不可学。这是可学习性本身的极限，不是工程问题。追求短期效用和保护泛化前提之间存在结构性张力。

第三条边界是泛化间隙：自动演化这条线，投入足够算力后回报会走平，而且和最好的监督学习相比还没有稳定的优势。有评测工作（EvoAgentBench，arXiv:2607.05202）查过：现有自动方法没有一个能在所有设定下持续正增益，而人类策展的内容能跨模型稳健迁移。

三条边界指向同一个分工：系统出候选，人类策展验收——决定什么该留、什么该淘汰、什么该提炼成方法论。

### 自演化三问：写得出来，才交得出去

哪些环节能交给系统自己演化？判据是三问：这个领域的**目标函数**写得出来吗，什么算更好；**实验流程**写得出来吗，有哪些可执行动作；**评估器**写得出来吗，怎么判定成败。三样缺任何一样，系统只能停在辅助位：产出再多，还得人逐条过目。

这是第 14 章 Razor 链条的倒数第二环：验证越便宜、进展越快，评估器自制就是把验证写进系统。人类策展也不是过渡方案：黄金集校准评判员就是这套判据的人工版本——先做一遍人的校准，再把校准交给系统。

未来线索一条：外置（写进上下文的技能）、内化（写进权重的后训练）、自演化（系统自我迭代）三步连起来看，系统开始有了"成长"的形状。但长多大，由三条硬边界说了算。

再远一格是**自修改智能体**（hyperagent）：把"改外部系统"的流程本身也做成可编辑对象——连产生改进的机制一起改。截至 2026 年 10 月，这一路还没做到全开放：任务分布、下一版的挑选与评估，都还是固定协议。

**潜通信**：协作的传输层直接交接隐状态，不再把计算压成文本。有工作在两个同构模型之间实现免训练纯潜协作，token 开销降七到八成、端到端提速 4 倍以上；代价是交接面没有文字记录，日志审计与跨交接的 trace 级评估都无从做起。这条线先记在这里。

## 丙部：模拟出来的社会 ▽

甲部答的是"哪里会翻车"，乙部答"能不能自己长"；丙部把这样一群智能体放进模拟环境让它们过日子，等于给社会科学家添了一种做实验的新方式：实验可以反复跑、每一步可以改。这种做法有个朴素的名字：**社会模拟**（social simulation）。社会模拟看到的不只是故障与自演化，还有一整片"社会现象"：语言、规范、角色、合作与信任，从互动里自己长出来。

社会模拟现在有三档做法，各有用处与代价。小规模（几十个智能体）可解释、可复现，适合看机制：Generative Agents 的 25 个居民，靠记忆、反思与日程，从一场情人节派对长出邀请扩散与约会配对。大规模（上万到上百万）能观察群体现象，代价是收紧单个智能体的自由度。AgentSociety 把通勤、就业与消费装进万级城市；OASIS 把社交媒体搬进百万级平台，信息扩散、群体极化、从众效应都能成规模地出现。开放世界（Project Sid 一类）让上千个智能体在 Minecraft 里长期生活，能看到职业分工、规则改写与文化传播，但这些仍是项目级、初步的结果。量级可信、细节随版本；"像社会"与"是社会"之间还有距离。

三档的取舍是同一条：规模越大，群体现象越明显，单个智能体的自由度越少。看机制先选小规模，看群体趋势再上大规模，开放世界适合看长期演化，结论也最不稳。

这套模拟的零件，前面几章都拆解过：记忆（§16 的三级台阶）、规划与反思迭代（§18 的四种形态）、工具（§16 的契约四步）。Generative Agents 的消融说得很直白：没有对经验记录的检索与定期反思，智能体几小时内就失去连贯。社会性不是凭空冒出来的，它靠的正是这几样零件。

"从互动里自己长出来"，能不能信？做一个最小的实验。**命名游戏**（naming game，Steels 的简化版）：一群智能体给一批事物起名字，开局没有任何公共词表。脚本 naming_game.py（assets/§19-体验实验/，无依赖）：24 个智能体、8 件事物；每轮随机挑两个智能体、一件事物，说的人有词就说出来、没词就现造，听的人没有就学会、不一样就改口。跑下来：约九千轮后整个群体收敛，每件事物只剩一个词（五个种子约六千到一万四千轮）；换种子重跑，八件事物的胜出词全换了一批：名字由互动历史一轮轮选出来。两个对照更说明问题。把交互切断，各造各的：每件事物上都攒下二十四个互不相同的词，永远聚不拢；反过来，开局给所有人发一张公共词表，"一致"第 0 轮就到齐，但那是复制，不是长出来。

于是立下三条判据：① 切断交互，现象还在吗（真长出来的，依赖互动史）；② 换种子换规模，结果会变吗（路径依赖说明是互动而不是先验在决定）；③ 有没有训练分布里没有的新东西（新词、新规范）。这里的"涌现"，与 §10 那个同词不同考场：那里问能力何时越过规模线，这里问现象从哪里来。第三问眼下最难：哪些行为从互动里长出来、哪些只是预训练行为的另一种回放，没有干净的分法。

模拟越像社会，好处与坏处就越清楚。协作的旁边，破坏性行为会一起冒出来（AgentVerse 一类的观察）。命名游戏这条线还给过两处读数：一群各自"没偏"的个体能长出集体的偏向，小规模的"铁杆"少数派能把既成约定整个翻过来（Ashery 等 2025，Science Advances；arXiv:2410.08948）。机制本身中立，可以被拿去演练说服与信息操纵——与 §17 的间接提示注入是同一张卷子的两面：那边防进来的字，这边研究发出去的字。往好里用，同一套技术能给系统做压力测试：先在模拟里把坑踩一遍，再谈上线。

两层别混：甲乙两部看工程层，丙部看行为层；看着像，未必是（§14 的第三问在这里原样再问一遍）。模拟是研究手段，不是现实本身。这一层最年轻，先记到这里。

## 动手：Pipeline 失败走查

拿甲部那套工具走一遍自己的流水线。题面：给三节点文档流水线（OCR 提取→翻译→摘要）在 A 端注入一个根因错误：把年份读错一位。沿 AgentFail 编号走查四格：根因在哪一层哪一类、沿哪条路径传播、在哪一跳暴露（距离几跳）、该在哪一端加什么校验；再说清为什么只加在暴露点的检查抓不住它。二十分钟，纸面完成。

交付一张四列表（根因—传播—暴露—校验点）加两句话的修复说明。验收标准：编号指认和类目表对得上；校验点必须位于传播路径的前端；能说清"暴露点检查为什么无效"。把这张表贴进你自己的笔记。

## 回望与下一章

甲部收一句：协作放大缺口，不制造能力。乙部收一句：自演化让外置的系统也能长，但三条硬边界把全自动划掉，稳定分工是系统出候选、人类做策展。这两句合起来是一条链：流程先被外置，再被内化，最后才进入自演化；过渡期多长，由硬边界决定。丙部也收一句：模拟里的"社会现象"，先用三条判据分一分哪些是真长出来的、哪些是训练数据的回声。

三题自查。

1. 一群智能体一起干活，会多出什么？分工的代价是什么，自演化能长到哪，社会模拟又多了什么？
2. Supervisor、Pipeline、Fan-out 三种拓扑各管什么？Debate 和 Swarm 各栽在哪？
3. AgentFail 把失败分成节点、结构、平台三层。OCR→翻译→摘要的走查里，根因、传播、暴露各在哪？为什么只在暴露点加检查没用？
